# Grill: Replace herdr with a pi-native subagent orchestrator

## Decisions made

- **Foundation: pi's official `subagent` example, copied to `pi/subagent/` and patched**: one-shot subprocess delegation (`pi --mode json -p --no-session`), not in-process SDK sessions. Rationale: maintained upstream, process isolation for free, stateless one-shot matches "subagents for autonomous tasks only", recursion guard is one env var instead of an in-process hack.
- **Spawnable roles: explore, implement, plan, review**: grill, teach, and janitor run in-session via their skills. Role files present in `.pi/agents/` = spawnable; the filesystem is the contract, no extra config.
- **Complete diff against upstream (~15 lines, nothing else)**: parse `thinking` frontmatter and pass `--thinking <level>`; set `NIXPI_WORKER=1` in the spawned child's env; factory guard `if (process.env.NIXPI_WORKER === "1") return;`. Keep the upstream tool name `subagent` for diffability against future pi versions.
- **Role file format: `name, description, model, thinking, tools`**: add `name:` to the four surviving roles; drop `skills:` and `prompt_mode:`. Append is the example's only mode, and workers get their skill through the role body's `cat ~/.pi/agent/skills/{name}/SKILL.md` instruction (skills are globally symlinked by activation).
- **Agent scope: upstream default `"user"`**: the tool reads global roles from `~/.pi/agent/agents/`. `.pi/agents/` stays the source that activation symlinks there. No confirmation prompts in this trusted repo.
- **Worktree contract**: the orchestrator always stays in the main checkout. Before delegating implement it creates the worktree (`git worktree add ../nixpi-dev-os-{NNN}-{slug} -b {NNN}-{slug}`) and passes `cwd: <worktree>`. explore/plan delegate with default cwd; review gets the same worktree cwd as the implement it reviews. Worktree removal (merge, then `git worktree remove`) is an in-session janitor duty at project close. The "plan and prior artifacts must be committed before implement" rule is unchanged.
- **Model selection stays in role frontmatter**: no per-call override in the tool. The model registry governs the recommend-and-confirm step before every delegation; changing a worker's model means editing the role file.
- **Bootstrap: 002 is implemented in-session**, because the implement builds the extension that would spawn it. In-session implement still follows the worktree convention above (edits target the worktree, not the main checkout). The first real use of the new `subagent` tool is delegating the review of 002 itself: dogfood and smoke test in one move.
- **Retirement scope**: delete `pi/herdr-agents/` entirely (including `role-parser.js`, replaced by the example's `agents.ts`, and its test suite); delete `.pi/agents/grill.md`, `teach.md`, `janitor.md`; remove herdr from `flake.nix` (input, package, `systemPackages` entry, `userActivationScripts.herdr` block). Rewrite AGENTS.md ("Skills and roles", "When the user says go", all pane references), README.md (herdr pin, roles paragraph, test commands), `resources/model-registry.md` (spawned phases = explore/plan/implement/review; in-session phases use the orchestrator's model), and one comment in `configuration.nix`.
- **Parallel and chain modes ship as-is, unused**: the workflow stays one worker at a time with model confirmation before each delegation. Keeping upstream code costs nothing; using it is not decided here.

## Explicitly ruled out

- **In-process SDK workers (`createAgentSession`)**: more wiring, shared event loop, `globalThis` recursion hack. The upstream example is simpler and crash-isolated.
- **Long-lived multi-turn workers (start/prompt/wait/collect handles)**: autonomous tasks are pure functions of (brief, committed repo state) producing an artifact. All handle/session-collector machinery dies.
- **tmux as the pane layer (earlier option C)**: visibility is no longer a requirement; worker progress streams into the orchestrator's tool-call rendering.
- **Spawning grill, teach, or janitor**: grill and teach are interactive (decisions belong to the user); janitor is a 2-minute chore. All in-session.
- **A new test harness for the extension**: it is upstream code plus ~15 patched lines. The dogfood review of 002 is the test.
- **Per-call model override in the tool**: YAGNI. Edit the role file.
- **Renaming the `subagent` tool**: keep upstream naming so future diffs against pi's example stay trivial.
- **Implementing 002 through the old herdr pipeline**: its last step would delete the floor under the running orchestrator session.

## Open questions (deferred)

- **Whether the example's collapsed/expanded progress rendering is enough visibility in practice** — decide after the first real delegation (002 review); user calls it.
- **Re-syncing `pi/subagent/` when pi bumps the example** — revisit on pi version updates; diff against upstream then, no standing process.

## Summary for downstream

Replace the herdr daemon and the `herdr-agents` bridge extension with a patched copy of pi's official `subagent` example at `pi/subagent/`: one-shot subprocess workers (`pi --mode json -p --no-session`) configured by role files (`name/description/model/thinking/tools`), with the only local patches being `thinking` support and a `NIXPI_WORKER=1` nesting guard. Spawnable roles are explore, implement, plan, and review; grill, teach, and janitor become in-session skills, and their role files are deleted along with all herdr code, flake inputs, and activation scripts. The orchestrator stays in the main checkout and passes an explicit worktree `cwd` to implement and review delegations (convention `../nixpi-dev-os-{NNN}-{slug}`, branch `{NNN}-{slug}`). Project 002 itself is implemented in-session (in its own worktree) and reviewed by delegating to the new tool as its first real use.
