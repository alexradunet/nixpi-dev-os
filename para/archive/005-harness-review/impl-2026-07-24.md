## Deviations (all reported, none behavioral)

1. **`index.ts` is 359 lines, over the plan's step-4.4 budget of < 300.**
   `execute` alone is 248 lines — it grew ~18 lines when the WS1 gate block
   landed (committed before this pass; not to be redone). The plan mandates
   `execute` stay whole in `index.ts`, so the budget and the content rule
   conflict; the content rule won. The plan's formal done-criteria and the
   task's hard cap are both < 500 — met.
2. **`renderResultRow` opts omit the plan sketch's `icon` field.** Icon
   placement differs per mode (single: leading; chain/parallel: trailing), so
   no single prepend/append works; `header` carries the fully constructed
   header row, keeping all three header rows byte-identical. Consequence of
   the mandated unification: single-mode's expanded view adopts the shared
   layout (inline `Task:` row; loses the `─── Task ───`/`─── Output ───`
   section labels and their spacers). Collapsed views, icons,
   `(Ctrl+O to expand)` hints, and the parallel running state are
   byte-identical to before.
3. **`formatUsageStats` keeps its live inline structural usage type** (live
   `index.ts` is the source of truth per the task brief) instead of importing
   `UsageStats`; `aggregateUsage`'s return lacks `contextTokens`, which the
   inline type's optional fields cover.
4. **`format.test.ts` expectation adjusted**: `formatTokens(2000)` is
   `"2.0k"` (the `< 10000` decimal branch), per step 3.3's instruction that
   the function is right and the expectation adjusts.
5. **Large method-block deletions from `index.ts`** (render methods ~314
   lines, spawn block ~213 lines) used line-exact `sed 'N,Md'` — pure
   deletion with no re-indentation, so nothing to corrupt; each deletion was
   verified via `git diff` review plus the live load smoke. All four new
   modules were written fresh with the write tool per protocol; `node --check`
   was never used as evidence — only the pi load smoke and the test suite.
6. **Plan grep quirks**: step 4.4's hand-rolled-listing grep necessarily
   matches `formatAgentList`'s own body in `agents.ts` (the plan's prescribed
   implementation contains the pattern) — zero occurrences in `index.ts`,
   which is the intent; step 5.4's `trusted-users` grep expects 1 but the
   plan's own snippet puts the word in a comment too (2 matches: comment +
   the single assignment).
