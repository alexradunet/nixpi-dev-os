## Why this matters

The extension today ships a hand-maintained `subagent` tool: ~1500 lines of
TypeScript (`index.ts` + `spawn.ts` + `render.ts` + `format.ts` + `core.ts` +
`agents.ts` + two test files) that spawn one-shot `pi` subprocesses. It works but
is a liability — it duplicates what the Paseo daemon already does better (worker
lifecycle, worktree workspaces, visibility, cross-provider reach), and it must be
reconciled against upstream pi on every bump. This plan deletes all of it and makes
Paseo the sole spawn layer. Pi stays the interactive orchestrator (playbook +
skills + PARA); the surviving `index.ts` is ~35 lines of hooks only. The cost of the
old tool (maintenance, nesting guards, env-var tricks, a trust gate) disappears; the
orchestrator drives Paseo with plain bash.

**This plan is executed through the OLD `subagent` tool — the harness it replaces.**
The implement worker reading this was spawned by that tool. Therefore the extension
must stay loadable and the `subagent` tool must stay functional until the final
switchover step (Step 8). Build all new docs/roles/skills alongside first (Steps
1–7, additive, the old tool is untouched); delete the tool machinery last (Step 8,
one atomic commit); then verify (Step 9). Because you work in a worktree, the main
checkout's extension (where the old tool actually runs) is never touched until merge,
so the harness that spawned you keeps working regardless. The ordering constraint
below is about keeping every commit on this branch loadable.

```ts
const PLAYBOOK_PATH = path.join(EXTENSION_DIR, "AGENTS.md");

function loadPlaybook(): string {
	try {
		return fs.readFileSync(PLAYBOOK_PATH, "utf-8");
	} catch {
		return "";
	}
}

export default function (pi: ExtensionAPI) {
	const playbook = loadPlaybook();

	// Skills and the playbook are served to every session, spawned workers
	// included: workers need the methodology (their role briefings reference
	// the skills by absolute path). Spawning itself is Paseo's job, so this
	// extension registers no tool.
	pi.on("resources_discover", () => ({ skillPaths: [SKILLS_DIR] }));
	pi.on("before_agent_start", async (event) => {
		if (!playbook) return;
		return { systemPrompt: `${event.systemPrompt}\n\n${playbook}` };
	});
}
```
