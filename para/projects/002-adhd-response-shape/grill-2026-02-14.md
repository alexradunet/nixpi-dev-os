# Grill: merging the i-have-adhd output rules into the orchestrator playbook

Source material: the `i-have-adhd` skill (pasted by the user; not installed on this system — it carries hermes marketplace metadata and lives elsewhere). Goal: agent output in pi sessions follows these rules by default, via the globally injected orchestrator playbook (`pi/orchestrator/AGENTS.md`).

## Decisions made

- **Split, don't dump**: prose-shaping rules fold into the existing Writing standards section; the six behavioral rules (lead with next action, number multi-step tasks, restate state, specific time estimates, end with one next action, make wins visible) get a new sibling section, "Response shape," placed directly after Writing standards. Rationale: Writing standards keeps its one job (artifact prose); the behavioral rules change day-to-day interaction and deserve a findable header.
- **No off-switch**: the skill's "stop adhd mode" / "normal mode" toggle is dropped. The kept escape hatch "user asks to explain → explain fully" covers long-form on demand; a standing toggle is YAGNI complexity in a playbook the user can edit in two minutes.
- **Escape hatches kept (5 of 6)**: (1) explain/walk-me-through → full explanation with headers, (2) destructive action → confirm first (covers in-session `rm -rf`, force push, migrations — the "What you never do" list only covers spawn/janitor), (3) debug spiral → after three "still broken" turns, stop iterating, name the suspect assumption, ask one diagnostic question, (4) real ambiguity → one clarifying question beats guessing, (5) a rule fights the task → the task wins, the shape stays (e.g. "what are my options" gets ranked options, recommendation first).
- **Escape hatch 6 dropped, spirit kept as a yield clause**: the skill's "the harness outranks the skill" rule inverts now that the rules live in the playbook itself. Replaced by one line: Response shape rules never override the "What you never do" list or the confirm-before-spawn / confirm-model gates. "Do the work instead of asking want me to" applies to in-session work only.
- **Pre-send check compressed**: the skill's five deletion rules mostly restate earlier rules; keep only the final verify — read only the first and last line of the response; they must say (a) what to do next and (b) what just happened.
- **Scope of the new section**: every response to the user. Workers are one-shot artifact writers; they already inherit prose discipline through Writing standards (the playbook is injected into worker sessions too — confirmed in `pi/orchestrator/index.ts`).
- **Time estimates point at whoever executes**: for delegated phases, the estimate is the worker's; for user steps, the user's. Concrete units only ("about 15 minutes," "an afternoon"), never "some work."

## Explicitly ruled out

- **A separate root-level `AGENTS.md`**: the orchestrator playbook is injected globally into every repo; a root file would only cover this repo and would duplicate context the playbook already carries.
- **One combined section for all ten rules**: would force Writing standards to expand its scope from artifact prose to chat behavior, bloating a section that is already dense.
- **Keeping the skill's persistence/toggle machinery**: meaningless in an always-on system-prompt context.
- **Modifying or deleting the source skill file**: it is not installed on this system and serves other harnesses (hermes). Out of scope.

## Open questions (deferred)

- None. The decision tree is fully walked; remaining choices are drafting (exact wording, bullet order) and belong to the implement phase.

## Summary for downstream

Merge the i-have-adhd skill into `pi/orchestrator/AGENTS.md` as two edits: (1) add the prose-shaping rules (no preamble/recap/closers, suppress tangents, cap lists at five, matter-of-fact error tone, no empty hedges or idioms) into the existing Writing standards section without changing its artifact-prose scope; (2) add a new "Response shape" section directly after Writing standards carrying the six behavioral rules, the five kept escape hatches, the yield clause subordinating everything to "What you never do" and the confirmation gates, and the compressed pre-send verify. No toggle, no changes to role files or skills, no other files touched. The edit is global by construction: the playbook is injected into every session, workers included.
