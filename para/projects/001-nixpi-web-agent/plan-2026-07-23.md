# Plan: nixpi-web-agent, a dependency-free pi skill for web research

## Goal

Ship a pi skill `nixpi-web-agent` (SKILL.md + Node `.mjs` scripts, Node built-ins only) that gives the agent DuckDuckGo search, HTTP-first page fetch to clean markdown with a headless-system-Chrome (CDP) fallback, and screenshots.

## Scope

In scope:
- `web-search.mjs`: DuckDuckGo HTML endpoint search, no API key, JSON output.
- `web-fetch.mjs`: HTTP-first fetch to markdown; thin/blocked/JS-rendered detection; CDP fallback via system Chrome; `--render` to force CDP; output modes `auto|inline|file` (supi-web semantics).
- `web-shot.mjs`: full-page or `--selector` screenshot via the same CDP driver.
- Generalized CDP driver kernel extracted (fresh code) from `balaur/.pi/skills/browser-check`.
- Graceful degradation: no pandoc → plain-text extraction; no chromium → HTTP-only with clear errors on the CDP paths.
- NixOS packaging: `chromium` + `pandoc` added to `environment.systemPackages`.
- Headless unit tests (`node --test`) for every pure function.

Non-goals (from grill): whole-site crawl, video/YouTube, OCR/PDF, multi-provider search fallback chains, settings UI, `doctor` command, playwright, npm dependencies, any copied pi-web-agent expression (AGPL-3.0).

## Resolved open questions (from grill)

1. **Extraction for the HTTP path: pandoc (nixpkgs) + JS prefilter, with a regex text fallback when pandoc is absent.** Pure-JS Readability needs npm deps (ruled out by the settled "no npm deps" decision); in-CDP Readability needs Chrome (defeats HTTP-first). Pandoc gives real markdown (links, headings, lists) in zero lines of our code; the fallback keeps HTTP-only mode working.
2. **Nix packaging: `environment.systemPackages` in `nixos/configuration.nix`.** That is the house mechanism (nodejs_24, git already live there); no new flake input, no derivation, no wrapper. Runtime binary probes in code handle degradation, so the skill partially works even before a rebuild.
3. **Skill placement: `pi_skills/nixpi-web-agent/` in this repo.** `configuration.nix` already symlinks every `pi_skills/*/SKILL.md` into `~/.pi/agent/skills/` on activation (verified: the seven workflow skills are symlinked there today). Zero new machinery; the skill ships with the config that provides its deps.
4. **Script granularity: three small CLIs (`web-search`, `web-fetch`, `web-shot`) sharing `scripts/lib/cdp.mjs`.** No separate `cdp-fetch` script: `web-fetch.mjs --render` covers forced rendering. No subcommand mega-script: each CLI stays single-purpose under ~150 lines.
5. **DuckDuckGo fallback posture: html endpoint first, `lite.duckduckgo.com` once on block/zero-results (same provider, same parser family, ~5 lines), then a clean exit-1 diagnostic naming the anomaly and pointing at the grill's documented SearXNG later-option.** Note: from this datacenter IP both endpoints are currently blocked (verified 2026-07-23: html serves an anomaly page, lite returns 202); search e2e here proves the diagnostic path, parser correctness is proven by fixture tests.

### File responsibilities and key functions

**`scripts/lib/args.mjs`** — one shared parser so the three CLIs don't duplicate flag logic.
- `parseArgs(argv, valueFlags)` → `{ flags: Record<string, string|boolean>, positional: string[] }`. `valueFlags` lists flags that consume the next token (`mode`, `selector`, `max`, `width`, `height`); other `--x` are booleans. ~12 lines.

**`scripts/lib/ddg.mjs`** — search, fresh regex parsing (no cheerio).
- `buildDdgSearchUrl(query, variant)` — `https://html.duckduckgo.com/html/?q=…` or `https://lite.duckduckgo.com/lite/?q=…`.
- `unwrapDdgRedirect(href)` — if host is `duckduckgo.com` and path `/l/`, return `decodeURIComponent(uddg)`; else the input. Protocol-relative `//` gets `https:`.
- `parseDdgResults(html, max)` — match anchors with class `result__a` (html endpoint) or `result-link` (lite), pair by order with snippets class `result__snippet` / `result-snippet`; decode entities; unwrap redirects; drop empties; cap at `max`. Returns `SearchResult[]`.
- `looksBlocked(html, status)` — true on status 403/429/202, or zero results plus `/anomaly|unusual traffic|not a robot/i` in body.
- `searchDuckDuckGo(query, { max = 10, fetchImpl = fetch } = {})` — fetch html endpoint; if `looksBlocked` or zero results, retry lite once; if still blocked, throw `Error` naming both endpoints and mentioning the SearXNG later-option; return `{ results, variant }`.

**`scripts/lib/http.mjs`** — plain HTTP fetch + weakness detection.
- `httpFetch(url, { fetchImpl = fetch, timeoutMs = 30000, userAgent = DEFAULT_UA } = {})` — GET with Chrome-like UA and `AbortSignal.timeout`; returns `{ status, ok, contentType, finalUrl, body }`; throws with the URL and cause on network failure.
- `isScriptShell(html)` — `<script` present and `id="app"` / `id="root"` / `id="__next"` present.
- `isThinContent(html, text)` — true when `text.length < MIN_USABLE_CHARS` (40), or script shell, or (`text.length < THIN_TEXT_CHARS` (120) and (density `text/html < 0.02` or `/enable javascript|javascript required|please turn on javascript/i`))). Constants at module top.

**`scripts/lib/html.mjs`** — HTML to clean markdown, pandoc optional.
- `decodeHtmlEntities(text)` — `&amp; &lt; &gt; &quot; &#39; &nbsp;` plus numeric decimal/hex.
- `extractTitle(html)` — regex on `<title>`, decode, collapse whitespace.
- `stripTagContent(html, tagNames)` — remove `<tag …>…</tag>` for each name.
- `prefilterHtml(html)` — strip `script style noscript svg template iframe nav footer`; keep `<main>` else `<article>` else `<body>` else whole input.
- `absolutizeUrls(html, baseUrl)` — rewrite `(href|src)="/…"` and `="//…"` to the base origin (regex, ~8 lines).
- `htmlToTextFallback(html)` — prefilter, strip remaining tags, decode, collapse whitespace; returns `MarkdownResult` with `engine: "fallback"`.
- `htmlToMarkdown(html, baseUrl, { pandocBin = "pandoc" } = {})` — absolutize, prefilter, `spawnSync(pandocBin, ["-f","html","-t","gfm","--wrap=none"], { input, encoding:"utf8", timeout: 20000, maxBuffer: 32MB })`; on ENOENT or non-zero exit return `htmlToTextFallback`; returns `MarkdownResult`. Pandoc injected as a parameter so tests pass a bogus bin to exercise the fallback.

**`scripts/lib/cdp.mjs`** — the generalized kernel (session subset of browser-check's `BrowserSession`; no console/network tracking, no Fetch interception, no input events).
- `findChromeBin(lookup = commandVLookup)` — first hit of `[google-chrome, google-chrome-stable, chromium, chromium-browser]`; `null` if none. Lookup injected for tests.
- `pickDebugPort()` — `9200 + floor(random*700)` (same collision posture as browser-check).
- `class CdpSession`:
  - `constructor({ width = 1440, height = 900 } = {})` — creates a `mkdtemp` profile.
  - `async start()` — throw if no binary (message lists the four tried names + the nix fix: `add chromium to environment.systemPackages, or: nix shell nixpkgs#chromium`); spawn `--headless=new --no-sandbox --disable-gpu --user-data-dir=… --window-size=W,H --remote-debugging-port=… about:blank`; poll `http://127.0.0.1:<port>/json` 40×250ms for a `type:"page"` tab; `new WebSocket(tab.webSocketDebuggerUrl)`; `Page.enable` + `Runtime.enable`.
  - `send(method, params)` — incrementing id, pending-map promise (browser-check pattern, rewritten).
  - `async evaluate(expression)` — `Runtime.evaluate` with `returnByValue, awaitPromise`; throw with the exception description.
  - `async navigate(url, settleMs = 800)` — `Page.navigate`, wait `document.readyState === 'complete'` (15s deadline, 200ms poll), fixed settle.
  - `async screenshot(file, selector = null)` — optional clip via `getBoundingClientRect` of the selector; `Page.captureScreenshot`; write base64 PNG.
  - `async close()` — close ws, kill chrome, `rmSync` own temp profile.

**`scripts/web-search.mjs`** — CLI.
- `main(argv)` — usage `web-search.mjs "<query>" [--max N]`; call `searchDuckDuckGo`; print `JSON.stringify(results, null, 2)` to stdout; one metadata line to stderr (`web-search: N results for "q" via html|lite`); errors to stderr, exit 1.

**`scripts/web-fetch.mjs`** — CLI + orchestration.
- `fetchViaCdp(url)` — `CdpSession` start → navigate → `evaluate("document.documentElement.outerHTML")` → close (in `finally`); returns html.
- `fetchPage(url, { render })` — if `render`, CDP directly; else `httpFetch`; non-2xx with chrome available → CDP retry; returns `{ body, contentType, finalUrl, method }`.
- `wrapNonHtml(body, contentType)` — fenced code block with a language hint (`json` for application/json, else empty).
- `chooseOutputMode(chars, mode)` — `auto` → `inline` when `chars <= AUTO_INLINE_LIMIT` (15000) else `file`.
- `emitMarkdown(markdown, meta, mode)` — inline: stdout; file: write `${tmpdir()}/nixpi-web-agent-<Date.now()>.md`, print `{path,url,method,chars}` JSON.
- `main(argv)` — usage `web-fetch.mjs <url> [--mode auto|inline|file] [--render]`; validate http/https URL (error includes the offending value); HTML path: `htmlToMarkdown` → if `isThinContent` and `findChromeBin()` → CDP re-fetch and re-extract; thin after CDP → exit 1 with `blocked: extracted N chars (< 40) from <url> via <method>`; thin with no chrome → emit what we have plus a stderr warning naming chromium; stderr metadata line `web-fetch: <finalUrl> via http|cdp, N chars, engine=pandoc|fallback`.

**`scripts/web-shot.mjs`** — CLI.
- `main(argv)` — usage `web-shot.mjs <url> [out.png] [--selector css] [--width N] [--height N]`; default out `shot.png`; start → navigate → screenshot → print `wrote <file>`; no chrome → exit 1 with the same binary-missing message.

**`SKILL.md`** — frontmatter `name: nixpi-web-agent`, `description:` one sentence covering search/fetch/screenshot and "HTTP-first with headless-Chrome fallback" (pi uses this for invocation). Body: prerequisites (node required; chromium + pandoc optional, from nixpkgs), the three commands with copy-paste examples, output-mode table, degradation table, caveats (DDG anomaly pages from datacenter IPs produce a clean diagnostic, SearXNG is the documented later-option; login/paywall pages: skip and ask the user, per supi-web guidance).

## Risks / open questions

1. **DDG blocks this datacenter IP** (verified 2026-07-23: html endpoint serves an anomaly page with 67 "anomaly" markers and zero result containers; lite returns 202). Search from this host exits 1 with the diagnostic by design. Parser correctness rests on fixture tests against the documented class names (`result__a`, `result__snippet`, `result-link`, `result-snippet`). If the block persists in real use, the grill's documented next step is an opt-in SearXNG backend. STOP-and-report, do not improvise: no proxies, no CDP-based search, no second provider.
2. **DDG markup drift**: fixtures are hand-written from the documented structure because live markup cannot be captured from this IP. When a session runs on a residential IP, capture a real results page and diff it against `test/fixtures/ddg-html-results.html`; update parser + fixture together if classes changed.
3. **`--headless=new` flag age**: needs Chromium ≥ ~112; nixpkgs chromium qualifies. If a future Chrome removes the flag, `start()` fails with the spawn error surfaced in the message; the fix is one flag, documented in cdp.mjs.
4. **Random debug port 9200–9899 collision** with a local service: low probability, same posture as browser-check; surfaces as a DevTools-poll timeout with a clear error.
5. **pandoc gfm quirks** on pathological HTML: prefiltering bounds the damage; the fallback engine guarantees non-empty output and stderr reports which engine ran.
6. Implementer STOP conditions: repo layout differs from this plan (drift); any temptation to add an npm dependency or copy upstream expression; `node --test` itself unavailable.
