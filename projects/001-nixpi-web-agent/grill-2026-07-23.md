# Grill: giving the pi agent minimal web-research (nixpi-web-agent)

## Context that shaped the decisions

- **Pi has no MCP, by design.** pi's README: "No MCP. Build CLI tools with READMEs (see Skills), or build an extension that adds MCP support." So any web tooling must bridge via a **skill** (agent calls scripts over bash) or an **extension**. This forced the skill-vs-extension question from the start.
- **`master-fetch` is "Hound" (`hound-mcp`)** — a Python MCP server (fetch/crawl/keyless-search/PDF-OCR/anti-bot). It ships an official pi extension `@houndmcp/hound-mcp-pi` that spawns `hound` as a stdio MCP subprocess. Requires Python 3.11+ `hound-mcp[all]` + patchright/Chromium.
- **`pi-web-agent` (demigodmode) is AGPL-3.0-only** (verified in package.json + LICENSE), not MIT. `pi-web-access` and `supi-web` are MIT.
- **The reusable gem in the user's own `balaur` repo**: `.pi/skills/browser-check` drives **headless Chrome over CDP using only Node's built-in `WebSocket`/`fetch` — no npm install, no WebDriver, no playwright**; prerequisite is just `google-chrome`/`chromium` on PATH. The CDP driver kernel is compact (spawn Chrome `--headless=new --remote-debugging-port`, `fetch /json`, `new WebSocket`, `Page.navigate`/`Runtime.evaluate`/`Page.captureScreenshot`); the surrounding ~1,500 lines are canvas-app smoke-test logic to discard.
- **Environment probe (this shell):** Node v24 present; **no Chrome/Chromium and no pandoc/lynx on PATH** → the skill must be HTTP-first and degrade gracefully, with browser/extraction deps declared via Nix.

## Decisions made

- **Use case = (b) research a topic across the web** → the tool needs exactly two capabilities: **web search** + **fetch-a-page-as-clean-text**. (The user's actual job; everything else was shopped against this.)
- **Build our own minimal `nixpi-web-agent`; do not adopt an existing package directly.** Rationale: KISS/minimal/own-it. Avoids Hound's Python+patchright+Chromium packaging tax, Firecrawl's multi-service stack, pi-web-access's third-party routing + 6.7 MB/5 deps, and pi-web-agent's AGPL copyleft on a vendored fork.
- **Use existing OSS as REFERENCES only — read for approach, write fresh minimal code, do NOT copy expression.** References: `pi-web-agent` (`src/search/duckduckgo.ts`, `src/fetch/http-fetch.ts`, `src/extract/readability.ts`, `src/orchestration/*`), `@mrclrchtr/supi-web` (`web_fetch_md` output modes: auto/inline/file). Rationale: stays clear of pi-web-agent's AGPL-3.0 (ideas/approach aren't copyrighted; copied expression would be), and keeps the result genuinely minimal.
- **Form factor = a pi SKILL (`SKILL.md` + `scripts/*.mjs`), not an extension.** Rationale: mirrors the user's existing `browser-check` skill being leveraged; no TS build step; no npm deps; pi loads markdown+scripts directly. Revisit only if bash-invoked scripts prove too clunky in practice (YAGNI: don't pre-optimize).
- **Leverage browser-check's zero-dependency CDP-over-system-Chrome technique** for JS-rendered/blocked pages: extract & generalize the CDP driver, discard the canvas smoke logic. Rationale: avoids the playwright/Chromium-download nightmare; reuses Chrome already present on the NixOS system; dependency-free.
- **No playwright.** System Chrome via raw CDP instead.
- **Search backend = DuckDuckGo HTML endpoint, no API key, no self-hosted service.** Rationale: KISS + private + honors AGENTS.md "no services unless a concrete present problem demands it." SearXNG self-hosted is a documented later-option only if DDG proves flaky.
- **Fetch strategy = HTTP-first, fall back to CDP** (system Chrome) when content is thin/JS-rendered/blocked. Rationale: Pareto — plain HTTP covers the 80% case cheaply; the browser is invoked only when needed.
- **Screenshot support = IN scope** (user override of the YAGNI default). Rationale: user wants it; nearly free because `Page.captureScreenshot` is already in the generalized CDP driver.
- **NixOS packaging = runtime deps declared via nixpkgs**: `node` (present), `chromium` (CDP path), optionally `pandoc` (HTTP→markdown). Graceful degradation to **HTTP-only mode** when no browser is present. Rationale: declarative/reproducible — the legitimate "nixpi-" kernel; avoids an impure playwright browser download.
- **Extraction (recommended default):** HTTP path → `pandoc` (nixpkgs) to markdown; CDP path → in-page Readability (browser provides the DOM). Planner may finalize vs. a pure-JS alternative.

### Target shape (for the planner)

A pi skill `nixpi-web-agent` with (names illustrative):
- `web-search.mjs "<query>"` → DuckDuckGo HTML endpoint → JSON `[{title,url,snippet}]`. No key, no service.
- `web-fetch.mjs <url> [--mode auto|inline|file]` → HTTP-first → clean markdown; detect thin/blocked content → fall back to CDP. Output modes inspired by supi-web.
- `cdp-fetch.mjs <url>` → generalized CDP driver: headless system Chrome → navigate → wait → extract rendered text (in-page Readability / `documentElement.outerHTML`).
- `cdp-shot.mjs <url> [--selector <css>] <out.png>` → `Page.captureScreenshot` (full page or element).
- Node built-ins only (`fetch`, `WebSocket`); no npm deps; no playwright.

## Explicitly ruled out

- **Hound / master-fetch as the engine:** Python + patchright/playwright + Chromium packaging burden on NixOS; heavy for the minimal goal (a turnkey pi extension exists but drags the whole engine).
- **Self-hosted Firecrawl:** multi-service Docker stack (Redis + Playwright + API + scraping service), no turnkey pi bridge, violates the Suckless / "no services unless a concrete problem demands it" principle. (Its capability is reachable later via a CDP/HTTP fallback if ever needed — no stack required.)
- **Install `pi-web-access`:** routes queries through third parties by default (Exa MCP, Jina Reader, encourages OpenAI/Brave/Tavily keys), 6.7 MB / 5 runtime deps, least suckless; conflicts with AGENTS.md "no data routed to a third-party scraper." Popularity (134.9K/mo) acknowledged but outweighed here by privacy/minimalism.
- **Install or vendor `pi-web-agent`:** AGPL-3.0 copyleft — a vendored/stripped fork stays AGPL on distribution. Chose to **reference** it instead of adopt/copy.
- **`supi-web`:** no web search (only Context7 library-docs lookup) — insufficient for use case (b).
- **Build-from-scratch / NIH:** rejected; resolved as "reference existing examples, write fresh minimal code."
- **Extension form factor:** skill chosen instead (no build step, mirrors browser-check).
- **Out of scope (YAGNI):** whole-site crawl, video/YouTube understanding, OCR/PDF, multi-provider search fallback chains, settings UI, `doctor` command.

## Open questions (deferred to planning)

- **Extraction implementation** — bundled `pandoc` (nixpkgs) vs pure-JS (`@mozilla/readability` + `jsdom`/`linkedom`) vs in-CDP Readability for the HTTP path. Recommendation: pandoc for HTTP + in-page Readability for CDP. Planner decides.
- **How the skill declares/pulls its Nix deps** — flake input, `environment.systemPackages`, a `nix shell`/`nix run` wrapper, or a small derivation. Planner / NixOS-packaging decision.
- **Skill placement** — `nixpi-dev-os` (this repo; note it currently uses root `pi_skills/`, whereas pi also discovers `.pi/skills/`, `.agents/skills/`, `~/.agents/skills/`) vs the `balaur` repo vs global. Planner decides; likely this dev-os repo.
- **Script granularity** — one `cdp` driver with `fetch`/`shot` subcommands vs separate scripts. Implementation detail.
- **DuckDuckGo endpoint robustness** — the HTML endpoint has anti-bot behavior; if flaky in practice, revisit SearXNG self-hosted as an opt-in backend. Deferred until tested.

## Summary for downstream

Build **`nixpi-web-agent`**, a minimal, dependency-free **pi skill** (SKILL.md + Node `*.mjs` scripts, mirroring the user's `browser-check` skill) that gives the agent web research for use case (b): **DuckDuckGo search (no key, no service)** and **HTTP-first page fetch → clean markdown**, falling back to a **generalized CDP driver over system Chrome** (extracted from `browser-check`, no playwright) for JS-rendered/blocked pages, plus **screenshot** support via the same CDP path. Write fresh minimal code using `pi-web-agent`/`supi-web` as **references only** (do not copy — keeps clear of pi-web-agent's AGPL-3.0). NixOS story: declare `node`/`chromium`/optional `pandoc` via nixpkgs and degrade gracefully to HTTP-only when no browser is present. Explicitly out of scope: crawl, video, OCR/PDF, multi-provider fallbacks, settings UI.
