## Issues encountered

1. **`.pi/agents/` was untracked.** The role files were never `git add`-ed (skills and extensions were), so the worktree had no `.pi/` and the roles could not be edited/committed on the branch as the plan assumed. Resolved with the lead's approval via option (A): a prep commit on `main` (`bb90d4b`) tracking the seven existing roles unchanged, then `git rebase main` in the worktree. This is a permanent, beneficial change (roles are now reviewed config) and was the only deviation touching `main`.
2. **Strict YAML parser vs. janitor's description.** The example's `parseFrontmatter` is a real YAML parser; `janitor.md`'s description contains `project: distill...` (colon+space), which throws "Nested mappings are not allowed" and crashes discovery rather than being skipped. The plan assumed the three non-keepers would be silently skipped (no `name:`). Since janitor is deleted anyway, I ran the Step 6 deletion before the Step 5 smoke so discovery only ever sees the four clean keepers. The four keeper descriptions contain no colon+space and parse cleanly (confirmed by the passing smoke).
3. **Plan's nix command syntax.** The plan used `--flake ./nixos_dev_env` with `nix flake lock`/`metadata`; that flag belongs to `nixos-rebuild`, not `nix flake`. Used the correct positional form (`nix flake lock .` from inside `nixos_dev_env/`).
4. **Plan's Step 4 whole-directory grep ordering.** `grep -L "^name:" .pi/agents/*.md` and the `skills:`/`prompt_mode:` grep assume the three deletions already happened (Step 6). Verified the four keepers individually at Step 4, then re-ran the whole-directory checks after Step 6 (both clean).
